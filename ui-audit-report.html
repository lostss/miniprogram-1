严重 交互流程 F-S1 客户搜索竞态：loading 守卫静默丢弃后续搜索请求 ›

问题：用户输入"a"搜索 in-flight 时，继续输入"ab"被 if (this.data.loading) return 静默丢弃，搜索框显示"ab"但列表仍是"a"的结果

位置：clients/index.js:15,34-38

修复：loading 改为请求ID追踪，不阻塞新请求；或取消旧请求再发新的

严重 交互流程 F-S2 OCR 编辑 sheet 无防重复提交，手动录入双击产生重复保单 ›

问题：onSheetConfirm 无 saving/busy 守卫，WXML 保存按钮无 disabled 绑定，快速双击会向 _procPolicies 推入两条相同保单并持久化到数据库

位置：ocr-flow/index.js:567-601 · ocr-flow/index.wxml:182

修复：onSheetConfirm 加 _saving 守卫 + 按钮 disabled="{{ocrSheet.saving}}"

严重 交互流程 F-S3 _doSave 成功后新成员角色补写失败被静默吞错 ›

问题：保单已写入成功，但若 apiGetFamily 返回 null（网络抖动），新成员角色永远不会被写入，用户看到保存成功但报告页家庭成员角色缺失

位置：ocr-flow/index.js:336-345

修复：fam 为 null 时 toast 提示 + 日志上报 + 重试机制

严重 交互流程 F-S4 checkResume 恢复后 _ocrBusy 未设置，300ms 窗口可被新 OCR 覆盖 ›

问题：恢复路径从未设置 _ocrBusy=true，300ms 延迟内用户点击上传会启动新 OCR，到期后 _procRefresh 用旧恢复数据覆盖新 OCR 的 upload 相位

位置：ocr-flow/index.js:78-87

修复：checkResume 确认后立即设 self._ocrBusy = true

严重 视觉 V-S1 --fw-regular 未定义但被引用，字重失效 ›

问题：app.wxss 仅定义 --fw-normal/medium/semi/bold，无 --fw-regular。.h1n-unit 字重失效回退为 normal

位置：report-markdown/index.wxss:11

修复：改引用 --fw-normal 或在 app.wxss 补定义

严重 视觉 V-S2 --warn 未定义且无 fallback，置信度徽章颜色完全失效 ›

问题：app.wxss 无 --warn 变量，.tone-badge 颜色完全失效，文字继承默认色，无法区分告警态

位置：edit-sheet/index.wxss:25

修复：app.wxss 补定义 --warn 或改引用 --amber

严重 视觉 V-S3 --ease-in-out 未定义，进度条动画 timing 失效 ›

问题：app.wxss 仅定义 --ease-out/in/out-expo/spring，无 --ease-in-out。进度条不定式动画回退为默认 ease

位置：ocr-flow/index.wxss:10

修复：改引用 --ease-out 或补定义

严重 视觉 V-S5 暗色模式覆盖完全缺失 ›

问题：全项目仅 1 个 @media（reduced-motion），无任何 prefers-color-scheme: dark 适配。系统暗色模式下页面仍是亮底，74个变量均为亮色固定值

位置：app.wxss

修复：增加 @media (prefers-color-scheme: dark) 覆盖核心变量

严重 视觉 V-S6 保障全景矩阵 overflow:hidden 裁剪溢出内容 ›

问题：pano 表格 overflow:hidden 直接裁剪溢出内容，窄屏/多成员场景数据丢失。对比 markdown-render 的表格正确用了 overflow-x:auto

位置：report-markdown/index.wxss:51

修复：overflow:hidden → overflow-x:auto

严重 状态反馈 R-S1 报告页未捕获异常导致空白页死胡同 ›

问题：_loadReport catch 块仅 console.error 并设 loading:false，family 保持 null。WXML 中 loading=false 且 family=null 时两个区块均不渲染，页面主区域完全空白，无错误提示无重试入口

位置：report/index.js:208 · report/index.wxml:3-15

修复：WXML 增加 !loading && !family 错误状态分支 + 重试按钮

严重 状态反馈 R-S2 报告页错误弹窗"留在本页"选项是死胡同 ›

问题：getFamily 返回 404（家庭已删除）时，用户点击"留在本页"后 loading=false 且 family=null，陷入空白页。家庭已不存在，留在本页无内容可看、无重试入口

位置：report/index.js:202

修复：404 场景下移除"留在本页"选项，或留本页时显示错误态+返回首页按钮

严重 表单 A-S1 OCR编辑表单数值字段弹文本键盘（无 keyboard-type） ›

问题：输入框无 type 属性，保额、保费、缴费年限等数值字段全部弹起文本键盘，用户需手动切换输入数字。对比 edit-sheet 已正确设置 type:'number'

位置：ocr-flow/index.wxml:176 · ocr-flow/index.js:663-696

修复：_buildSheetFields 数值字段补 type:'digit'

严重 表单 A-S2 OCR编辑表单"编辑模式"完全无校验 ›

问题：编辑已有保单时仅 trim 后直接写回，不校验产品名称必填、不校验数值格式（保额可填"abc"）、不校验日期格式、不校验长度。脏数据直接进入 _procPolicies 并最终写库

位置：ocr-flow/index.js:587-600

修复：复用 edit-form.js 的 validate 逻辑或内联校验

严重 表单 A-S3 OCR编辑表单"手动录入"仅校验产品名称 ›

问题：仅 if (!np.product_name) 一行校验，保额、保费等数值字段可填任意非法字符串后保存，无类型/范围/格式校验

位置：ocr-flow/index.js:567-586

修复：补全数值字段 Number() 校验、日期格式校验

严重 表单 A-S4 edit-sheet 字段级校验基础设施完全闲置 ›

问题：edit-sheet 内置了 required/maxLen/pattern 校验逻辑及 onFieldBlur 实时校验、_validateAll 保存校验，但 edit-form.js 所有字段配置均未设置这些属性。失焦校验永不触发、必填星号永不渲染、实时反馈完全失效

位置：edit-form.js:17-25,35-39,53-66 · edit-sheet/index.js:47-73

修复：edit-form.js 字段配置补 required/maxLen/pattern，激活已有校验能力

位置：report/index.js:371 · edit-sheet/index.js:81-84

问题：ERROR_MAP 覆盖 400/401/403/404/500/NETWORK/TIMEOUT/UNKNOWN，但未包含 429。AI 服务频繁返回 429，回退到 UNKNOWN → "操作失败，请重试"。而 ocr-flow.js 的 errorToUI 正确映射 429 为"AI服务繁忙"

问题：errorToUI 精心映射了每个错误码的 {title, content}（如"请确认图片清晰后重试"），但 errorLabel 仅返回 ui.title，content 中的恢复引导文案被完全丢弃，错误卡只显示标题无具体建议

位置：ocr-flow.js:341-402

五大关键结论

1. 最大风险：竞态与防重复提交

F-S1（搜索竞态）、F-S2（sheet双击）、F-S4（resume窗口）三处均为快速操作下的数据丢失/重复问题，建议优先修复

2. 最差体验：错误恢复路径断裂

R-S1/S2（空白页死胡同）、R-M4（下拉重试无效）、R-M5（错误伪装空态）让用户卡死无出路

3. 最大浪费：校验基础设施闲置

A-S4（edit-sheet 内置完整校验但字段未配置），已有能力未启用，补配置即可激活实时反馈

4. 视觉系统：token体系完整但执行不彻底

74个变量定义完善，但6处未定义引用 + 大量硬编码绕过 + 暗色模式完全缺失

5. 正面发现：防御性设计值得保持

OCR流程进度反馈较完善、删除有双重确认、防重入守卫覆盖主链路、骨架屏与渐进加载设计良好、减少动效偏好已支持
