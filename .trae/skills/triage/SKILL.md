# Triage

Move issues on the project issue tracker through a small state machine of triage roles.

Every comment or issue posted during triage **must** start with: `> *This was generated by AI during triage.*`

## Roles

Two **category** roles: `bug`, `enhancement`

Five **state** roles: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`

Every triaged issue should carry exactly one category and one state role.

State transitions: unlabeled → `needs-triage` → `needs-info`/`ready-for-agent`/`ready-for-human`/`wontfix`. `needs-info` returns to `needs-triage` after reporter reply.

## Invocation

The maintainer invokes `/triage` in natural language. Examples:
- "Show me anything that needs my attention"
- "Let's look at #42"
- "Move #42 to ready-for-agent"

## Show what needs attention

Present three buckets, oldest first:
1. **Unlabeled** — never triaged
2. **`needs-triage`** — evaluation in progress
3. **`needs-info` with reporter activity** — needs re-evaluation

## Triage a specific issue

1. **Gather context.** Read full issue, explore codebase, read `.out-of-scope/*.md`.
2. **Recommend.** Category + state with reasoning, wait for direction.
3. **Reproduce (bugs only).** Attempt reproduction before any grilling.
4. **Grill (if needed).** Run `/grill-with-docs` session.
5. **Apply the outcome.**
   - `ready-for-agent` — post agent brief comment
   - `ready-for-human` — same structure, note why can't be delegated
   - `needs-info` — post triage notes
   - `wontfix` — explanation, close or write to `.out-of-scope/`

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:** (points)

**What we still need from you (@reporter):** (specific, actionable questions)
```
