# 保单整理报告（探索版 · MVP 内测）设计

> 状态：探索版设计 · 2026-10-13 · 分支 `explore/checkup-report`（基线 `73abc6e`）
> 上游：`specs/mvp-report-20260929/design.md`（已被本轮**收窄**：只做"整理"，不做检视）

## 0. 定位

**把散落的保单整理成一份能逐条核对的清单。** 读者是代理人与客户**同看**（代理人操作手机，当面或微信里一起过），目标是让客户产生「我的保单你看清了」的信任；客户可带走一份脱敏回看版。

**产品阶段（2026-10-13 用户决策）**：

| 阶段 | 产物 | 状态 |
|------|------|------|
| 阶段一 | **保单整理报告**（本 spec）——只做归集/汇总/标注 | 当前；「当前报告降级成保单整理报告」 |
| 阶段二 | **保障检视报告**——在同一份报告上增加段落（缺口/条款责任/时间轴/观察） | 未来扩展方向 |

由此得出两条架构约束（**不建抽象**）：
1. 输出保持「事实白名单 + 分节」形状（`header/summary/groups/unassigned/pending`），阶段二＝在同一份数据上**增加段落**，不需要插件/主题机制
2. 阶段一的 `organize.js` **不得**掺入缺口/建议逻辑（那是阶段二的段落，混进来会同时破坏红线 1 与可判定性）

**入口落点**：家庭页（`pages/report/index`）内的「保单整理报告」入口——与流程（建档 → 家庭页 → 上传保单 → 报告）一致；客户列表页不再单独放入口（单一入口，判据才好归因）。

三条红线（沿用，且是本次探索要验证的核心）：

| # | 原则 |
|---|------|
| 1 | 只出结果，不出建议——缺口/优先级/配置方案一律不做 |
| 2 | 不加形容词——只写「有什么 + 值」，不写好/坏/不足 |
| 3 | 不确定就标出来，不猜——缺字段、低置信、被保人未匹配，显式列出 |

## 1. 本轮范围（尽量简化）

| # | 段落 | 内容 |
|---|------|------|
| ① | 抬头 | 客户/家庭 · 成员数 · 保单数 · 数据来源与截止时间 |
| ② | 一屏汇总 | 保单张数 · 总保额（**一年期短险单列**并注明每年需续保）· 年缴保费合计 · **已覆盖险种枚举** |
| ③ | 按成员分组 | 每个成员（**含无保单成员**）下列其保单卡：产品名/险种/保额/保费/期间/生效日/状态/来源 |
| ④ | 未匹配保单 | 被保人不在成员名单的保单，单独一栏（不猜归属） |
| ⑤ | 待完善 | 缺关键字段 · 低置信字段 · 被保人未匹配，可逐条点开修正 |
| ⑥ | 免责与来源 | 数据来源、口径说明、脱敏说明 |

## 2. 明确不做（本轮）

- 缺口 / 优先级 / 建议 / 评语（含"事实级观察"——延后，见 §5）
- 条款责任对照（依赖 `products` 建档，且应用侧目前零引用该集合）
- 保障时间轴 / 甘特图、保费三切面与缴费月历
- 现价表 / 回本
- AI 进入报告正文（本轮报告为纯规则产物，可复现）
- 快照/版本落库（最贵的持久化决策，等假设验证过再设计）

## 3. 数据与隔离开关

- 取数：**零云函数改动**——复用 `getFamily`（`loadFamilyView` + `loadActivePolicies`，已带 `_openid` 与 deleted 过滤）
- 组装：`miniprogram/utils/checkup/organize.js`（**纯函数**，输出视图模型，不落库、不含 `_openid`）
- 入口：新增独立页 `pages/checkup`，由 `miniprogram/utils/explore-flags.js` 的常量开关控制入口可见性（全仓原无任何 flag 机制，本开关一并建立）
- 客户版：沿用现有分享脱敏链（`dataQuery/share.js`），本轮不新做脱敏实现

## 4. 内测判据（探索的验收，不是功能的验收）

同一份报告，2~3 位代理人各自与真实客户同看一次，记录：

| 信号 | 期望 |
|------|------|
| 客户是否主动追问（张数/保额/到期对不上） | 出现 ≥1 次 → 说明"整理"看进去了 |
| 客户是否愿意带走回看版（分享点击） | 出现 → 信任信号 |
| 代理人是否愿意第二次用（下次约见） | 出现 → 工具有留存价值 |
| 是否出现"这是不是推销/建议"的抵触 | 出现 → 红线 1/2 被违反，需改措辞 |

**kill criteria**：客户对清单无反应、或代理人觉得比"直接念保单"更费口舌 → 停止加码，不进入条款对照与时间轴。

## 5. 延后项（下一轮再定）

条款责任对照（需 5 产品建档 + 8 个补 `benefits`）· 事实级观察（规则算、AI 讲）· 保障时间轴 · 快照与版本 · 旧 AI 诊断的去向。

⚠️ **"降级"的边界待拍板（本轮明确不动）**：客户版分享（`dataQuery/share.js`）目前会下发 **AI 叙事 + 缺口结论**。若"降级成整理报告"要在**客户可见面**上成立，就得同步收起这两项（`share.js` 一处 + 前端 `isShared` 分支过滤）；若只在代理人侧降级，则客户同看时仍会看到诊断，与红线 1（不出建议）矛盾。二选一，未定前不动。
