# 活报告模型 2026-09-06 — 需求

范围：保障检视报告的产品模型基线。经 2026-09-06 从北极星多轮推演收敛（量入为出单报告 + AI 常驻自动分析 + 采集闭环 + 客户端信任环）。本文件锚定需求；design/tasks 后续产出，均锚定于此。
术语：报告 = 基础报告（7 章规则引擎，事实层）+ 保障分析（AI 叙事层；现状代码文案为"深度分析"，术语统一另议，不阻断本基线）。

## 北极星（S0）

代理人对客户保单**整理**后出具一份保障检视报告：
- 对代理人：方便了解客户家庭保障缺口（内部工作视角，owner 工作台保留底稿类展示）。
- 对客户：认知当前家庭的保障缺口及背后的原因。
- 质量底线：报告始终在"当下信息边界内正确"——宁缺毋滥，不基于残缺信息下误导性结论。

## 核心命题

报告是活文档（CONTEXT：publishing 非 CRUD）。**只有一个报告**，信息到什么程度，内容自然长到什么深度（量入为出），无"版本/档位"的用户可见概念。

## R1 · 报告量入为出

- 背景：量化内容（缺口金额/保额目标/预算框架）依赖家庭经济数据；事实/结构层（保单+成员角色年龄，OCR 自动推导）恒可呈现。
- 目标：
  - 事实/结构层：覆盖现状、险种级缺口（有/无）、AI 定性解读（缺什么、为什么、出事后果）——经济数据缺失时**恒完整可出**。
  - 量化层：仅当经济数据齐备（家庭年收入为必要项）出现；缺失时缺口章仅险种级、量化内容自动隐藏；补全后自动出现。
  - 档位由数据完备度自然涌现（复用 `readiness` 结果派生），不新增判定引擎、不新增用户可见档位 UI。
- 非目标：不改基础 7 章规则引擎定位；不引入"版本/档位"概念。

## R2 · AI 保障分析自动介入（贝叶斯式更新）

- 背景：AI 本质是替代代理人分析——真实代理人按已有信息判断，新信息到达后迭代修正。现状保障分析仅手动触发，新档案原因层缺位（Gap A）。
- 目标：
  - 显著信息更新（`writeSeam` 置 `insight_stale=true` 后）→ 批量合并防抖 → 自动触发重算；窗口内连续变更合并一次。
  - **反模式：每写必算**。仅显著更新重算：新保单入库、家庭结构变化、经济数据到位等。
  - 无新变更（`insight_stale=false`）不重算；分析成功置 false，失败保持 stale 可重试。
  - 生成后可校对/可撤销：错误观测不得自动传播（对接 OCR 确认卡/画像确认/`writeSeam` 撤销）。
  - readiness 角色从"生成前门槛"转为"观测校验位 + 缺失清单派生源"，不阻塞报告生成。
- 非目标：不做时间到期强制刷新；不做后台常驻轮询；节流窗口/成本上限具体值留 design。

## R3 · 采集闭环（追问机制 + 对话采集线接入）

- 现状：对话侧信息采集钩子**已实现**（`conversationAI/prompts.js` 结尾引导：选择式轻问、附理由、禁钩子内计算缺口/下保额结论、豁免纯记录与闲聊、宁缺毋滥）——采集端已就位。
- 目标：
  - 保障分析产出尾部挂"为深化需澄清的 N 项"（报告侧；时序 B：分析**后**追问，非分析前门禁）；代理人线下问客户 → 补录 → 触发下一轮更新；可跳过、不阻塞事实层。
  - 对话采集钩子与报告侧待澄清项**同源派生**（同一缺失清单），防两处重复骚扰。
  - 采集对象=代理人；载体复用对话与既有补录路径（成员/财务表单、对话工具），不新增专用追问 UI 系统。
- 非目标：不做客户自助写路径（客户端不直面 AI 填敏感数据）；不新增"客户完善意愿"系统级提醒实体（YAGNI，先观察）。

## R4 · 客户端信任环

- 背景：客户未必向代理人提供完整真实信息（信任/敏感），但报告需要诚实与可持续。不采用"客户直面 AI 自曝"旁路（信任损伤 + 把关权丧失 + 观测无校验）。
- 目标：
  - 客户版报告含**正向提示**："报告将随家庭成员/收支信息更新而自动刷新"——教育"报告是活的、会因我而更准"，杜绝"信息不全/仅供参考"类示弱表述。
  - 引导客户经**现有微信会话**与代理人沟通补全（分享链路即桥梁）；不新增客户侧交互系统。
  - 分享 token 页实时渲染：代理人补全更新后，客户再次打开同一链接可见更新内容。
- 非目标：不做客户自助录入；不做客户侧待办/通知实体。

## R5 · 报告结构定稿（四层漏斗 + 版块治理）

- 背景：2026-09-06 版块价值评估确认——现有报告结构基本成立（owner 底稿/客户版裁剪边界正确），核心问题为：缺口语义被多层重复平铺、`last_summary` 产而无显、缺"报告是活的"感知位及 R3/R4 挂载位。
- 目标：
  - **四层结构**（两读者共用骨架，层间职责显性）：
    1. 页头 + Hero：元数据 + **时效标识**（挂载点①）+ 三数字摘要 + AI 一句话结论 + 覆盖检查（结论速览）
    2. **保障分析（主叙事层，客户恒展开）**：core_insights → 画像 → 点评 → 缺口根因 → 配置建议 → 行动清单，尾部挂**"为深化需澄清的 N 项"**（挂载点②）
    3. 事实数据层（按需展开）：覆盖矩阵 → 缺口明细（量化随经济数据出现/降级）→ 保障节点/缴费月历（默认折叠）→ 附录·保单明细（默认折叠）
    4. 收口：免责声明（静态模板）+ footer（owner：转发/导出 PDF；客户：水印 + **沟通桥正向引导**，挂载点③）
  - **版块治理**（确认项）：
    - 客户版默认只铺 1-2 层（hero + 保障分析），事实数据层折叠——缺口语义在客户视图中不重复平铺。
    - 行动出口去重：客户版行动主出口 = 保障分析行动清单；⑧规则行动章的保留/并入由 design 定（owner 保留核对口径）。
    - `last_summary`（家庭保障结构标签）接线渲染（hero/页头副题落点，两版可用）。
    - C0 生成入口卡：R2 自动介入落地后移除；过渡期保留。
    - owner-only 底稿：①家庭结构 ②家庭财务 ⑦置信度告警（观测校验位）仅 owner 屏显。
    - **量化降级说明**（挂载点④）：经济数据缺失时客户版出现克制说明（"补全家庭收支后将补充保额测算"），措辞与 R4 一致，不示弱、不泄内部口径。
  - 挂载点汇总：①时效/新鲜度标识（页头）②待澄清项（分析区尾部）③沟通桥引导（客户 footer/hero 下）④量化降级说明（缺口章/hero 脚注）。
- 非目标：不引入保险常识科普版块、版本变化 diff、条款对比（YAGNI，无需求证据）。

## 验收准则（EARS）

- When 家庭经济数据缺失，then 报告事实/结构层与 AI 定性解读完整呈现，量化层（缺口金额/预算框架）不出现，缺口章仅险种级。
- When 家庭经济数据补全（收入/负债录入），then 报告在防抖窗口内自动出现量化内容（缺口金额、预算框架），无需手动触发。
- When 防抖窗口内发生连续批量变更（OCR 多张/编辑多步），then 自动分析合并为一次；重复触发被现有 CAS 机制拒绝。
- When 无数据变更（`insight_stale=false`），then 不触发任何保障分析。
- When 保障分析完成，then 其产出（若存在影响深化结论的缺失项）包含"待澄清项"清单；代理人已回答或标记跳过的项不再重复出现。
- When 对话中自然涉及保障/健康/收入话题且存在待补全项，then AI 以选择式轻问呈现且附理由（影响核保/保额锚点），不计算缺口、不追加无关引导；纯记录确认/闲聊不加任何引导。
- When 任一家庭数据写入，then 经 `writeSeam` 统一置 `insight_stale=true`；错误观测可撤销，撤销后不向报告传播。
- When 客户打开分享报告，then 可见"报告随信息更新自动刷新"的正向引导，无贬义完整度表述；代理人补全后客户再次打开可见新内容（token 未过期）。
- When owner 打开报告页，then 底稿类信息（置信度/缺口依据/优先级）与完整量化内容可见，编辑/对话能力不变（北极星代理人视角）。
- When 客户打开分享报告，then 默认可见层为 hero 结论速览与保障分析主叙事，事实数据层折叠态可展开；缺口语义不以多区域重复平铺呈现。
- When 保障分析已生成且存在影响深化结论的缺失项，then 报告分析区尾部展示"为深化需澄清 N 项"清单（挂载点②），非阻塞可跳过。
- When 家庭经济数据缺失，then 客户版量化缺口行不出现，并附克制说明"补全家庭收支后将补充保额测算"（挂载点④），无内部口径/公式泄漏。
- When 页头展示报告时效，then 区分"数据更新于 / 保障分析生成于"；数据已变更而分析未刷新时可见提示（挂载点①）。
- When 保障分析生成/更新完成，then `last_summary` 在页头/hero 有渲染落点（家庭保障结构标签），不再存在产而无显的 AI 字段（`last_disclaimer` 除外，静态模板替代）。
- When 客户查看 footer 区，then 可见"报告随信息更新自动刷新，可联系服务顾问完善信息"的正向引导（挂载点③），无客户自助录入入口。
