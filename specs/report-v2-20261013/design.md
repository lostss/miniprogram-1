## 诊断层

### ⑤ 诊断点评（规则引擎 + AI 分治）

**分工铁律**：算得清的用规则，读得懂的用 AI。

| 诊断项 | 引擎 | 输出 |
|---|---|---|
| 保障覆盖全面性 | 规则 | 结构有无判断 + 红黄灯 |
| 保额充足性 | 规则 | 覆盖率% + 缺口金额（绝不让 LLM 做算术） |
| 保障期间完整性 | 规则 | 空白期/重叠期（甘特图副产品） |
| 已有保险责任点评 | AI+RAG | 含什么/不含什么/理赔条件/免责要点 |
| 已有增值权益 | AI+RAG | 电话医生、体检解读、保单贷款等隐藏权益 |
| 诊断结论"人话翻译" | AI | 把规则引擎的数字翻译成客户语言 |

> ✅ **已是现状**（v2.0 此处是确认而非新建）：`cloudfunctions/reportAI/report-context.js:89` 预算缺口矩阵，`reportAI/prompts.js:172` 明令"直接引用、禁止重算"。

**AI 四条铁律**：

1. **溯源引用**：每条 AI 结论可展开定位条款原文（"不含外购药"←责任免除第 X 条）。检索不到时输出"该产品条款暂未收录"，禁止自由发挥。
2. **结构化输出**：AI 填 JSON 模板（维度/结论/条款引用/置信度/通俗解释），版式稳定、可缓存、可回归测试。
3. **产品级缓存**：同一款产品的责任点评全客户复用，成本随产品种类数增长而非保单数增长；新品首次解析→人工抽检→入库。
4. **错误不对称**：漏报可容忍（保守），误报趋近于零。负面结论必须有明确免责条款原文支撑，否则输出"未检出，建议与保司核实"。

> ⚠️ **评审必改③（当前不可交付）**：`products` 在运行时 JS **零引用**；只存概念化字段 + `source.url`，**无"责任免除第 X 条"级原文/条目号**；已建档仅 **8 个产品**（`docs/prd.md:220`）。→ 现在实现，绝大多数保单都会落到"暂未收录"，模块只剩成本。
> **前置两条独立工程线**：① 建档时保留**原文段落 + 条目号**（`extract-pdf.js` 已拿到全文，只是没入库）；② 消费端按产品名匹配并注入。
> **不要上向量检索**：8 个产品量级用关键词精确匹配 + 条款版本号更可靠、可缓存、可抽检。
> ⚠️ **缓存键必须含条款版本**（否则条款更新后旧结论被复用 = 误报）。更简单的等价做法：**建档时预计算**（离线 + 人工抽检），报告期只做注入 + 翻译。
> ⚠️ **建议改位置**：AI 责任点评从"报告生成时"移到**按产品懒加载**（点开某张保单才生成）→ 缓存天然按产品、成本骤降、单点失败不毁整份报告。现状最坏路径已 3 次 AI 调用（`reportAI/index.js:450`，`ATTEMPT_TIMEOUT_MS=40000`，`FN_LIMIT_MS=60000`）。
> ✅ 第 2 条**已实现**：`responseFormat:{type:'json_object'}` + `_shared/parse-ai-json.js:21-57` 三级容错 + 预算内重试一次（`reportAI/index.js:238-279`）。

## 合规三不原则（写入 guardrail）

1. 不做产品价值判断（事实陈述"有什么缺什么"，不说"好不好"）
2. 不做绝对化承诺（"肯定能赔"进敏感词黑名单）
3. 免责声明前置（"AI 辅助生成，仅供参考，以条款为准"），AI 内容双层呈现：客户版精简 + 代理人版含引用与置信度

> ⚠️ **评审（现状差距，逐条）**：
> ① "不做价值判断"**仅在 prompt 文本**（`reportAI/prompts.js:58`），无输出后校验；
> ② 只有"禁止赔付/收益承诺"是**代码硬拦**（`_shared/guard.js:93-103 FORBIDDEN_CLAIMS` + `:112-141 auditOutput`），且**报告场景降级为 warn 不阻断**（`reportAI/index.js:449`）→ 要落地第 1/2 条需把校验扩到"产品贬损"并把报告场景改为**拦截**；

**① TOP-N 风险预警（模块 ① 的前半部分）**

| 项 | 实现 |

### 6.1 后两项：年度保费趋势 + 下一期缴费（2026-10-14）

用户稿子的 ②「保费按年度趋势：缴费期满后保费下降曲线，释放的现金流可再配置 ⭐」与 ⑤「关键节点：下一期缴费（第 N 期）」。

**做法：先建两个跨树契约，再让页面与 PDF 同时消费** —— 这一项天生要"页面 + 纸面"两处出现，若各写一份就是又一次口径分裂（reportPdf 在期限口径上已经吃过一次亏）。为此顺带**收敛了双字段期限口径**：

| 契约 | 内容 |
|---|---|
| `_shared/policy-terms.js`（新） | 保障期/缴费期的双字段口径（`insurance_period` 文本优先、`coverage_term` 数字兜底；105=终身、1=趸交）。此前散在 timeline-builder 与 reportPdf._termYear 两处；现**前端那份收敛为唯一实现**（timeline-builder / gantt-builder / premium-trend 共用）。⚠️ reportPdf._termYear 仍是遗留的第二份（已部署、被 71 条测试覆盖），收敛它属独立重构，已记在契约头注释里 |
| `_shared/premium-trend.js`（新） | 年度保费曲线 + 下降台阶 + 下一期缴费（含"第几期"）。页面（缴费月历章）与 PDF（缴费月历节）**同源**；契约文件一致性有测试断言 |

**口径与两次实施中修掉的真错**（都由端到端实跑暴露，单测当时全绿）：

1. **趸交被报成"下一期缴费"** —— 趸交是一次性支出，之后没有"期"可言 → 排除（+ 单独 note）。
2. **最后一张保单缴满的次年台阶被漏掉** —— 曲线末端要多算一年，否则"保费降到 0"这个最有价值的点不出现。
3. **一年期短险被整类排除** —— 线上最常见形态（真实家庭 13 份保单里 6 份一年期），且**通常没有 `payment_period`** → 按"缺缴费期"排除等于漏掉最该提醒缴费的一类。现口径：**下一期缴费照常提醒**；年度曲线**只计当前年度**（不替客户假设"会一直续保"，与"短险不虚高保障感"的既有口径一致）。
4. **一年期短险产生了假的"缴费期满"台阶** —— 修正 3 之后，它"次年不再出现"会被渲染成"2027 年起降至 X 万（百万医疗缴费期满）"，而它其实是每年续保 → 台阶与曲线**只用长期险**口径计算（趸交同理）；当年总保费仍含全部保单，与同章"年总保费"行对得上。

**PDF 同步**：缴费月历节加"下一期缴费 + 台阶 + notes"行（与页面同文案）。已部署（`reportPdf` ModTime **2026-10-14 21:20:32**）+ 冒烟 `{code:401}`。

⚠️ **本轮抓到一个 lint 才发现的运行期 bug**：PDF 里首版写成 `buildPremiumTrend(activePolicies, …)`，而 `activePolicies` 是**另一个函数（调用层）**的变量名，`buildPdf` 作用域内只有 `act` → **导出 PDF 必 ReferenceError**。更糟的是我当时的测试断言 `toContain('buildPremiumTrend(activePolicies')` **把这个 bug 锁住了** —— 与 09-28 记入质量错误库的反模式同型（源码文本断言冒充运行验证）。修法：改用 `act`；并把断言换成"**实参标识符必须在 buildPdf 函数体内、调用点之前已声明**"（已反向验证：坏样本 `activePolicies` 会红）。**教训重申**：这类作用域问题只有 `eslint no-undef` 或真实执行能抓到，文本断言零检出。
