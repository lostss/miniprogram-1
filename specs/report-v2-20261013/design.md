## 诊断层

### ⑤ 诊断点评（规则引擎 + AI 分治）

**分工铁律**：算得清的用规则，读得懂的用 AI。

| 诊断项 | 引擎 | 输出 |
|---|---|---|
| 保障覆盖全面性 | 规则 | 结构有无判断 + 红黄灯 |
| 保额充足性 | 规则 | 覆盖率% + 缺口金额（绝不让 LLM 做算术） |
| 保障期间完整性 | 规则 | 空白期/重叠期（甘特图副产品） |
| 已有保险责任点评 | AI+RAG | 含什么/不含什么/理赔条件/免责要点 |
| 已有增值权益 | AI+RAG | 电话医生、体检解读、保单贷款等隐藏权益 |
| 诊断结论"人话翻译" | AI | 把规则引擎的数字翻译成客户语言 |

> ✅ **已是现状**（v2.0 此处是确认而非新建）：`cloudfunctions/reportAI/report-context.js:89` 预算缺口矩阵，`reportAI/prompts.js:172` 明令"直接引用、禁止重算"。

**AI 四条铁律**：

1. **溯源引用**：每条 AI 结论可展开定位条款原文（"不含外购药"←责任免除第 X 条）。检索不到时输出"该产品条款暂未收录"，禁止自由发挥。
2. **结构化输出**：AI 填 JSON 模板（维度/结论/条款引用/置信度/通俗解释），版式稳定、可缓存、可回归测试。
3. **产品级缓存**：同一款产品的责任点评全客户复用，成本随产品种类数增长而非保单数增长；新品首次解析→人工抽检→入库。
4. **错误不对称**：漏报可容忍（保守），误报趋近于零。负面结论必须有明确免责条款原文支撑，否则输出"未检出，建议与保司核实"。

> ⚠️ **评审必改③（当前不可交付）**：`products` 在运行时 JS **零引用**；只存概念化字段 + `source.url`，**无"责任免除第 X 条"级原文/条目号**；已建档仅 **8 个产品**（`docs/prd.md:220`）。→ 现在实现，绝大多数保单都会落到"暂未收录"，模块只剩成本。
> **前置两条独立工程线**：① 建档时保留**原文段落 + 条目号**（`extract-pdf.js` 已拿到全文，只是没入库）；② 消费端按产品名匹配并注入。
> **不要上向量检索**：8 个产品量级用关键词精确匹配 + 条款版本号更可靠、可缓存、可抽检。
> ⚠️ **缓存键必须含条款版本**（否则条款更新后旧结论被复用 = 误报）。更简单的等价做法：**建档时预计算**（离线 + 人工抽检），报告期只做注入 + 翻译。
> ⚠️ **建议改位置**：AI 责任点评从"报告生成时"移到**按产品懒加载**（点开某张保单才生成）→ 缓存天然按产品、成本骤降、单点失败不毁整份报告。现状最坏路径已 3 次 AI 调用（`reportAI/index.js:450`，`ATTEMPT_TIMEOUT_MS=40000`，`FN_LIMIT_MS=60000`）。
> ✅ 第 2 条**已实现**：`responseFormat:{type:'json_object'}` + `_shared/parse-ai-json.js:21-57` 三级容错 + 预算内重试一次（`reportAI/index.js:238-279`）。

## 合规三不原则（写入 guardrail）

1. 不做产品价值判断（事实陈述"有什么缺什么"，不说"好不好"）
2. 不做绝对化承诺（"肯定能赔"进敏感词黑名单）
3. 免责声明前置（"AI 辅助生成，仅供参考，以条款为准"），AI 内容双层呈现：客户版精简 + 代理人版含引用与置信度

> ⚠️ **评审（现状差距，逐条）**：
> ① "不做价值判断"**仅在 prompt 文本**（`reportAI/prompts.js:58`），无输出后校验；
> ② 只有"禁止赔付/收益承诺"是**代码硬拦**（`_shared/guard.js:93-103 FORBIDDEN_CLAIMS` + `:112-141 auditOutput`），且**报告场景降级为 warn 不阻断**（`reportAI/index.js:449`）→ 要落地第 1/2 条需把校验扩到"产品贬损"并把报告场景改为**拦截**；
